# lucafchala.com

> The apex site and **hub** of Luca F. Chala's self-hosted web ecosystem — the personal landing page, the PURL (short-link) source of truth, and the canonical reference for the design system and conventions every sibling repo follows.

**Live:** [lucafchala.com](https://lucafchala.com) · **Stack:** static HTML/CSS/JS on Cloudflare Pages · **Build step:** none

---

## What it is

**One sentence:** `lucafchala.com` is a static, bilingual (PT‑BR / EN), dark‑/light‑themed personal landing page served from Cloudflare Pages, which also ships the site's short‑URL redirect rules (`_redirects`), a custom `404`, a migration notice, and a `/status` redirect to the status dashboard.

**In a paragraph:** This repository is the front door of a small constellation of single‑purpose sites (photography, radio, pastes, short URLs, status, a control panel, and more), each deployed independently under a `*.lucafchala.com` subdomain. There is no framework and no build: every page is hand‑written HTML with inline CSS and vanilla JavaScript, and Cloudflare Pages serves the files as‑is on every push to `main`. Because this is the namesake repo and the place the visual identity originates, it doubles as the **ecosystem hub**: the [ecosystem map](#the-ecosystem) below describes every sibling repo and how they fit together, and the [design system](#design-system) section is the single source of truth that the other repos link back to so the whole network stays visually and structurally consistent.

> **Working on a sibling repo?** Link to this README's [Design System](#design-system) and [Shared conventions](#shared-conventions) sections instead of re‑documenting them. Keep one source of truth.

## The ecosystem

Every site is its own GitHub repository and its own Cloudflare deployment. Nothing shares a server; they are tied together by a common design system, a common host (Cloudflare), and the control panel (`dash`) that writes redirect/paste data into several of them.

| Repo | Domain | Platform | Role |
|---|---|---|---|
| **lucafchala.com** (this repo) | `lucafchala.com` | Cloudflare Pages (static) | Apex landing page, PURL `_redirects`, `404`, migration notice, `/status` redirect |
| **dash.lucafchala.com** | `dash.lucafchala.com` | Cloudflare Pages (static SPA) | Private control panel; edits PURLs & pastes and **writes them into the other repos** via the GitHub Contents API |
| **url.lucafchala.com** | `url.lucafchala.com` | Cloudflare Pages (static) | Read‑only public directory of all PURLs + a hub grid; generated by `dash` |
| **paste.lucafchala.com** | `paste.lucafchala.com` | Cloudflare Pages (static) | Pastebin — `pastes.json` + one static page per paste; managed by `dash` |
| **status.lucafchala.com** | `status.lucafchala.com` | Cloudflare Pages + **Pages Functions** | Live status dashboard with email subscription/alerts (Resend + Workers KV) |
| **portal_radio** | `radio.lucafchala.com` | Cloudflare Workers (static assets) | Amateur‑radio portal: per‑callsign profiles, live APRS tracking, PIX donations |
| **restricted** | `restricted.lucafchala.com` | Cloudflare Worker + KV | A capture‑the‑flag puzzle with a public leaderboard |
| **fotos** | `fotos.lucafchala.com` | Cloudflare Worker + KV | Photo gallery with admin dashboard, LGPD removal flow, metrics (own design system) |
| **spectral-drift** | static (domain not pinned in repo) | Static page | Generative wave‑interference art (p5.js) with a hidden end‑to‑end‑encrypted P2P chat |
| **OMG.LOL_transfer** | — (tooling, not deployed) | Node scripts | Migration hub: omg.lol export scripts, exported content, and generated `output/` for the repos above |

**Other subdomains in the network** that are referenced across these sites but live in their own separate repos/deployments (not part of this checkout): `keys`, `proof`. (`now` and `weblog` were discontinued and redirect to `/transferring`.)

### How data flows between repos

Most repos are independent static sites. The exception — and the glue of the ecosystem — is **`dash`**, which uses a GitHub Personal Access Token to commit generated files straight into the other repos. On save it writes:

```
repoHome  (lucafchala.com)   →  _redirects, 404.html
repoDash  (dash)             →  data.json
repoPaste (paste)            →  pastes.json, {slug}/index.html
repoUrl   (url)              →  _redirects, data.json, index.html, 404.html
```

Writes are **sequential within a single repo** (two commits racing on one branch cause a GitHub `409`) and **parallel across repos**. A push to any repo triggers that repo's own Cloudflare deploy. So editing a short link in `dash` ends up live on both `lucafchala.com/<slug>` and `url.lucafchala.com` within seconds, with no manual file editing.

## Architecture (this repo)

- **Host:** Cloudflare Pages, serving the repo root statically. No build command.
- **Deploy trigger:** every push to `main` → automatic Cloudflare Pages deployment.
- **CI:** GitHub Actions — `checks.yml` validates JSON, internal links and that the CSP hashes in `_headers` cover every inline script; `smoke-test.yml` hits key routes after each deploy.
- **Runtime:** 100% client‑side. Inline JS handles language, theme, the command palette (`/` or ⌘K), copy‑to‑clipboard, the São Paulo clock and the easter eggs.
- **Consumes:** nothing third‑party on the homepage — fonts are self‑hosted in `fonts/`. (Cloudflare's own Web Analytics beacon is injected at the edge and allowed by the CSP.)
- **Exposes:** the landing page (`/`), the redirect slugs defined in `_redirects` (e.g. `/instagram`, `/review`), the `/status` redirect, and a custom `404`.

## Prerequisites

To work on the site you need almost nothing:

- A text editor and `git`.
- (Optional) any static file server for local preview — e.g. `npx serve`, `python3 -m http.server`, or the VS Code *Live Server* extension. There is **no** `npm install` and **no** build.

To deploy you need:

- Push access to the `lucafchala/lucafchala.com` GitHub repo.
- The Cloudflare Pages project connected to that repo (already configured; one‑time setup done in the Cloudflare dashboard).

## Install & deploy

```bash
# 1. clone
git clone https://github.com/lucafchala/lucafchala.com.git
cd lucafchala.com

# 2. preview locally (pick any static server)
python3 -m http.server 8000        # → http://localhost:8000
# or: npx serve .

# 3. edit index.html / 404.html / _redirects / status/index.html …

# 4. ship it
git add .
git commit -m "describe your change"
git push origin main
```

Cloudflare Pages picks up the push and deploys within seconds. There is nothing to build and nothing to configure per deploy.

> Redirect rules and the `404` are normally **not** edited here by hand — they are generated and committed by [`dash`](https://github.com/lucafchala/dash.lucafchala.com). Edit them in `dash` to keep `lucafchala.com` and `url.lucafchala.com` in sync. See [How to use → PURLs](#purls--the-_redirects-file).

## How to use

### The landing page (`index.html`)

A single long page, mobile‑first:

- a sticky **top bar** with the monogram, an **Instagram** shortcut, a **search** button (command palette), the **PT/EN** switch and a **theme** toggle;
- the **hero** — live São Paulo clock, the name, roles with callsign **PU2XIK**, CTAs (photos · Instagram · contact), and (desktop) a section index;
- the **bio** with drop cap and an at‑a‑glance facts grid (base, camera, callsign, next step);
- **01 Fotografia** — a featured **Instagram** card (travel photos + live event stories), recent galleries from `fotos` and a camera‑kit summary linking to the full gear list;
- **02 Rádio** — a QSL‑card styled station summary (QTH, grid, zones, rig, modes) plus profile / QRZ / portal links;
- **03 Contato** — email (compose + copy), WhatsApp, Signal, SimpleX, Pix support and social links;
- **04 Ecossistema** — every subdomain with a one‑line description;
- **05 Verificação** — the PGP fingerprint (copy), keys, proof and keys.openpgp.org;
- a footer with `73 de PU2XIK`, utility links and keyboard shortcuts.

Translations live inline in the `i18n` object in `index.html`; the email link is assembled in JS (`website@lucafchala.com`) to dodge naive scrapers. Language defaults to the browser's, theme to the OS preference; explicit choices persist in `localStorage`.

### PURLs — the `_redirects` file

Short, memorable paths that 301‑redirect to long destinations, in [Cloudflare Pages redirect syntax](https://developers.cloudflare.com/pages/configuration/redirects/):

```
/<slug>  <destination>  301
```

Rules are grouped by comment headers (`contact`, `events`, `video`, `tools`). Examples from the live file:

```
/instagram     https://www.instagram.com/lucafchala                301
/review        https://forms.gle/AoMuMFPj9TFuzS3H8                  301
/a-mascara_yt  https://youtu.be/QBcq8sRf81c                         301
```

The same rule set is published read‑only at [`url.lucafchala.com`](https://url.lucafchala.com). **Both are generated by `dash`** — edit short links there, not by hand, so the two stay identical.

### Status redirect (`status/index.html`)

A script‑free page that meta‑refreshes to [`status.lucafchala.com`](https://status.lucafchala.com), the real dashboard (server‑side functional checks + email alerts, in the separate [`status.lucafchala.com`](https://github.com/lucafchala/status.lucafchala.com) repo). The old client‑side view here could only detect total outages and was blocked by the CSP.

### `404.html` and `transferring.html`

- **`404.html`** — a domain‑aware not‑found page (the same file is deployed to `lucafchala.com` and `url.lucafchala.com`; it adapts its "see all links" button at runtime via `location.hostname`). Generated by `dash`.
- **`transferring.html`** — a holding page for addresses still being migrated off omg.lol, pointing visitors to `suporte@lucafchala.com` and to `url.lucafchala.com`.

## Design system

This is the **canonical reference** for the shared visual language used by `lucafchala.com`, `dash`, `url`, `paste`, and `status` (and the `pu2xik` profile in `portal_radio`). Sibling repos should link here rather than restating it.

> Not every repo uses this system. `fotos`, `restricted`, `spectral-drift`, and the `portal_radio` landing + other callsign profiles each have their **own** palettes and fonts, documented in their READMEs. The rules below apply only to repos that opt into the shared identity.

### Fonts

- **Cormorant Garamond** (serif) — display: names, titles, large headings. Italic accents are common.
- **JetBrains Mono** (monospace) — everything else: body, labels, buttons, metadata.

Sibling repos load them from Google Fonts with exactly this stylesheet (the apex homepage self‑hosts the same families from `fonts/` — latin subset, variable weight — to avoid a third‑party request):

```html
<link href="https://fonts.googleapis.com/css2?family=Cormorant+Garamond:ital,wght@0,300;0,400;0,600;1,300;1,400;1,600&family=JetBrains+Mono:wght@300;400;500&display=swap" rel="stylesheet">
```

### Color tokens

Set on `:root` (dark, the default) and overridden under `[data-theme="light"]`:

| Token | Dark | Light | Used for |
|---|---|---|---|
| `--bg` | `#0d0c0a` | `#f4efe6` | Page background |
| `--border` | `#252220` | `#d8d1c4` | Hairline borders, dividers |
| `--text` | `#e6e1d6` | `#1c1a17` | Primary text |
| `--muted` | `#948a7c` | `#6b6152` | Secondary text, labels (≥ 4.5:1, WCAG AA) |
| `--faint` | `#6a6358` | `#9a8f80` | Decorative only (old `--muted` values — too low‑contrast for text) |
| `--accent` | `#c08030` | `#8a5712` | Amber highlight, links, active state (light value darkened for AA) |
| `--accent-dim` | `#6a4818` | `#c89050` | Dimmed accent (arrows, hovers) |
| `--ctrl-bg` | `#161412` | `#ede8df` | Control backgrounds, cards |

The **status** service extends this set with state colors — `--up #4a8c5c`, `--degraded #8c6a20`, `--down #8c3a3a` (dark variant) — for its badges.

### Layout & motion

- **Canvas:** `font-size: 14px; line-height: 1.75`, content `max-width: 680px` (the homepage uses `760px`, the `url` directory `720px`), centered, `padding: 48px 32px 72px`; on mobile `32px 22px 52px`. **Mobile‑first** (Samsung S26 Ultra is the primary device).
- **Theme is restored before first paint** with a tiny inline script reading `localStorage.theme` (falling back to `prefers-color-scheme` on the homepage), so there is no flash of the wrong theme. Mark inline scripts `data-cfasync="false"` so Cloudflare Rocket Loader doesn't defer them.
- **Grain overlay:** a fixed, pointer‑events‑none SVG `feTurbulence` fractal‑noise layer at `opacity: 0.28` gives the warm paper texture.
- **Entrance animation:** the `rise` keyframe — `opacity: 0; translateY(18px)` → settled — at `0.9s cubic-bezier(0.16,1,0.3,1)`, staggered with small delays down the page.

### Shared components

`.controls` / `.controls-inner` / `.ctrl-btn` (top toggle bar), `.rule` (labeled section divider, e.g. `CQ DE PU2XIK`), `.hub` (service card in the `url` grid), `.act-btn` (inline copy/open button), `.name` (clamped Cormorant display heading). Copy these patterns rather than inventing new ones.

The homepage adds a few more: `.topbar` (sticky, blurred bar; `.ctrl-group` replaces `.controls-inner` with `aria-pressed` buttons), `.sec-head` (numbered serif section heading), `.card` / `.kicker` (bordered card with a small uppercase header), `.linklist` (title + description rows), `.btn-primary` / `.btn-ghost` / `.mini-btn`, `.chips`, `.qsl` (QSL‑card block) and `.palette` (`<dialog>` command palette).

## Shared conventions

Conventions every repo in the network is expected to follow:

- **No build step, no framework, no bundler.** Hand‑written HTML/CSS/JS, served statically (Pages) or from a single Worker file. (`fotos`, `restricted` use a Worker; the rest are static.)
- **Deploy by pushing.** Cloudflare watches `main`; there is no separate build command for the static sites.
- **Bilingual where it matters:** PT‑BR primary, EN secondary, toggled client‑side.
- **Dark/light theme** persisted in `localStorage` under `theme`, restored before paint.
- **Cloudflare `_redirects`** for short links: `/<slug>  <dest>  301`.
- **Don't edit generated files by hand** (`_redirects`, `data.json`, `pastes.json`, the `url` index, the shared `404`) — change them through `dash`.

---

## Technical decisions

- **Why no framework / build step?** The content is small and changes rarely. Plain files mean zero toolchain rot, instant deploys, no dependency upgrades, and pages that still open by double‑clicking years from now. The trade‑off — some copy‑pasted CSS between repos — is accepted in exchange for that durability.
- **Why split every site into its own repo + subdomain?** Independent blast radius and deploys: a broken push to `fotos` can't take down the landing page, and each project can use the platform that fits it (Pages for static, Workers + KV for stateful apps).
- **Why GitHub‑as‑database for `dash`?** It avoids running a backend just to edit a handful of redirects and pastes: the data already needs to live in git to deploy, so the control panel commits to git directly using a PAT, and Cloudflare turns those commits into deploys.
- **Why Cloudflare?** Free static hosting + Workers/KV/Pages Functions under one account, automatic HTTPS, and a global edge — enough to run the whole network at no cost.
