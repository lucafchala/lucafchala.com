# lucafchala.com

> The apex site and **hub** of Luca F. Chala's self-hosted web ecosystem: the personal landing page, one of the two places the short links (PURLs) are served, and the canonical reference for the design system and conventions every sibling repo follows.

**Live:** [lucafchala.com](https://lucafchala.com) · **Stack:** static HTML/CSS/JS on Cloudflare Pages · **Build step:** none

---

## What it is

**One sentence:** `lucafchala.com` is a static, bilingual (PT‑BR / EN), dark/light personal landing page on Cloudflare Pages. It also ships the short‑link redirect rules (`_redirects`), a shared `404`, a migration notice and a `/status` redirect.

**In a paragraph:** This repository is the front door of a small constellation of single‑purpose sites (photography, radio, pastes, short URLs, keys, proof, status, a control panel and more), each deployed on its own `*.lucafchala.com` subdomain. There is no framework and no build step. Every page is hand‑written HTML, CSS and vanilla JavaScript, and Cloudflare Pages serves the files as they are on every push to `main`. The visual identity comes from here, so this repo is also the **ecosystem hub**. The [ecosystem map](#the-ecosystem) describes every sibling repo, and the [design system](#design-system) and [shared conventions](#shared-conventions) are the single source of truth the other repos link back to.

> **Working on a sibling repo?** Link to this README's [Design system](#design-system) and [Shared conventions](#shared-conventions) instead of re‑documenting them.

### How data flows between repos

Most repos are independent static sites. The glue is **`dash`**. It commits generated files straight into the other repos through its `/api/github` Pages Function, which holds the GitHub token (`GH_PAT`) server‑side. On a PURL save it writes:

```
dash repo      data.json                      ← the source of truth, written first with the SHA read at load
                                                (if someone else changed it meanwhile → conflict dialog, nothing else is written)
lucafchala.com _redirects, 404.js, 404.html
url            _redirects, data.json, url.js, index.html, 404.js, 404.html
```

and on a paste save:

```
paste repo     pastes.json (gate, same conflict check), {slug}/index.html shells, sitemap.xml
```

How the writes are run:
- **Order:** sequential within a repo (two commits racing on one branch cause a GitHub `409`), parallel across repos.
- **Skipping:** files whose content hasn't changed are skipped, so a save only commits what changed and triggers only the builds it needs.
- **Script before page:** each script is written before the HTML that loads it, so no intermediate deploy serves a page whose script doesn't exist yet.

Every push triggers that repo's own Cloudflare deploy. Editing a short link in `dash` is live on both `lucafchala.com/<slug>` and `url.lucafchala.com` within seconds.

## Architecture (this repo)

- **Host:** Cloudflare Pages, serving the repo root statically. No build command.
- **Deploy trigger:** every push to `main` → automatic Cloudflare Pages deployment.
- **Runtime:** 100% client‑side, in three files:
  - `theme.js` — loaded synchronously in `<head>`; applies the theme before first paint.
  - `app.js` — language, command palette (`/` or ⌘K), copy‑to‑clipboard, the São Paulo clock, the easter eggs.
  - `style.css` — all styles.

  The only inline `<script>` is the JSON‑LD data block, which never executes.
- **CSP:** `script-src 'self'` plus Cloudflare Web Analytics. There are **no hashes to maintain**: every executable script is a file.
- **CI** (GitHub Actions):
  - `checks.yml` validates JSON, internal links, and that no inline script or `on*=` handler would be blocked by the CSP.
  - `smoke-test.yml` runs on every push to `main` (after waiting until Cloudflare Pages serves the pushed version of a changed file), daily, and on demand. It requests the key routes and assets and checks:
    - the CSP header, with no `'unsafe-inline'` in `script-src`;
    - that `/instagram` and `/pgp` redirect correctly;
    - that an unknown path is the generated 404;
    - that `security.txt` has at least 30 days left.

    It used to trigger on `deployment_status`, which Pages never sends, so it never ran.
  - `checks.yml` also runs monthly: its `security.txt` step fails when `Expires` is less than 30 days away. The same step exists in proof.lucafchala.com.
- **Consumes:** nothing third‑party. Fonts are self‑hosted in `fonts/`. Cloudflare's Web Analytics beacon is injected at the edge and allowed by the CSP.
- **Exposes:** the landing page (`/`), the short links in `_redirects` (e.g. `/instagram`, `/review`), the `/status` redirect, and the shared `404`.

```bash
git clone https://github.com/lucafchala/lucafchala.com.git
cd lucafchala.com
python3 -m http.server 8000        # → http://localhost:8000
# edit index.html / style.css / app.js …
git add . && git commit -m "describe your change" && git push origin main
```

## Configuration

This repository needs **no environment variables and no secrets**. The only runtime state is client‑side:

| Where | Key | Values | Purpose |
|---|---|---|---|
| cookie on `.lucafchala.com` | `lf_theme` | `dark` \| `light` | Theme, **shared by every `*.lucafchala.com` site**: a choice made on one sticks on all |
| cookie on `.lucafchala.com` | `lf_lang` | `pt` \| `en` | UI language, shared the same way |
| `localStorage` | `theme`, `lang` | same | Per‑origin fallback when the cookie is absent |

Without a saved choice, the theme follows `prefers-color-scheme` and the language follows `navigator.language`.

## How to use

### The landing page (`index.html` + `style.css` + `app.js`)

A single long page, mobile‑first:

- **Sticky top bar:** monogram, **Instagram** shortcut, **search** (command palette), **PT/EN** and **theme** toggles.
- **Hero:** live São Paulo clock, name, roles with callsign **PU2XIK**, CTAs (photos · Instagram · contact), and on desktop a section index.
- **Bio:** drop cap and an at‑a‑glance facts grid.
- **01 Fotografia:** featured Instagram card, recent galleries from `fotos`, camera‑kit summary.
- **02 Rádio:** QSL‑card station summary and profile / QRZ / portal links.
- **03 Contato:** email (compose + copy), WhatsApp, Signal, SimpleX, Pix, social links.
- **04 Ecossistema:** every subdomain with a one‑line description.
  - **Live status dot:** a dot on each card, read from `status.lucafchala.com/api/resumo` (a ~1 KB, CORS-open summary that only reads status's D1 snapshot).
    - It only shows when status serves its shared D1 snapshot (`retratoCompartilhado`), so homepage visitors never trigger a sweep.
    - With no snapshot, or on any error, there are no dots.
    - Colours are `--up` / `--degraded` / `--down`, with a ring and screen-reader text so colour isn't the only signal.
- **05 Verificação:** PGP fingerprint (copy), keys, proof, keys.openpgp.org.
- **Footer:** `73 de PU2XIK`, utility links, shortcuts.

Translations live in the `i18n` object in `app.js`. Elements carry `data-i18n` / `data-i18n-aria`, and the PT text in the markup is the no‑JS fallback. The email address is assembled in JS to dodge naive scrapers.

### PURLs — the `_redirects` file

[Cloudflare Pages redirect syntax](https://developers.cloudflare.com/pages/configuration/redirects/), grouped by comment headers (`contact`, `events`, `video`, `tools`):

```
/<slug>  <destination>  302
```

Links are **302 by default**. Browsers cache a 301 permanently, so a changed destination would never reach anyone who already followed the old one. Individual links can be marked permanent (301) in dash. Cloudflare applies `_redirects` **before** static files, which is why dash refuses slugs that match a file on the site (`robots.txt`, `status`, `fonts`, …).

The same rules are served by [`url.lucafchala.com`](https://url.lucafchala.com), which lists them. Both are generated by dash from its `data.json`.

### `404.html` + `404.js`

The same pair is deployed to `lucafchala.com` and `url.lucafchala.com` (generated by dash). The page:
- is PT/EN and `noindex`, and follows the shared theme/lang preferences;
- shows a toast with the decoded slug when you arrive through a bad short link;
- **suggests the closest existing links** (edit distance against the list in `url.lucafchala.com/data.json`);
- has a "← Voltar" button that falls back to `/` when there's no history.

All behaviour is in `404.js`, loaded from `'self'`, so the page needs nothing special in the CSP.

### `status/index.html` and `transferring.html`

- **`status/index.html`** — a script‑free meta refresh to [`status.lucafchala.com`](https://status.lucafchala.com), the real dashboard.
- **`transferring.html`** — holding page for addresses moved off omg.lol.

## Design system

The **canonical reference** for the shared visual language used by `lucafchala.com`, `dash`, `url`, `paste`, `keys`, `proof`, `pays` and `status` (and the `pu2xik` profile in `portal_radio`).

> `fotos`, `restricted`, `spectral-drift`, and the `portal_radio` landing and other callsign profiles have their **own** palettes and fonts, documented in their READMEs.

### Fonts

- **Cormorant Garamond** (serif): display — names, titles, large headings; italic accents are common.
- **JetBrains Mono** (monospace): everything else — body, labels, buttons, metadata.

**Every site self‑hosts them.** Copy `fonts/` (latin subset, variable weight, OFL licences included) and use:

```css
@font-face { font-family: 'Cormorant Garamond'; font-style: normal; font-weight: 300 700; font-display: swap; src: url('/fonts/cormorant-garamond-latin.woff2') format('woff2'); }
@font-face { font-family: 'Cormorant Garamond'; font-style: italic; font-weight: 300 700; font-display: swap; src: url('/fonts/cormorant-garamond-italic-latin.woff2') format('woff2'); }
@font-face { font-family: 'JetBrains Mono'; font-style: normal; font-weight: 300 500; font-display: swap; src: url('/fonts/jetbrains-mono-latin.woff2') format('woff2'); }
```

with `font-src 'self'` in the CSP. Don't link Google Fonts: the zone's Cloudflare Fonts feature rewrites those links to same‑origin `/cf-fonts/…` files, which a `font-src https://fonts.gstatic.com` CSP then blocks. That silently broke the fonts on every subdomain until September 2026.

### Color tokens

Set on `:root` (dark, the default) and overridden under `[data-theme="light"]`:

| Token | Dark | Light | Used for |
|---|---|---|---|
| `--bg` | `#0d0c0a` | `#f4efe6` | Page background |
| `--ctrl-bg` | `#161412` | `#ede8df` | Control backgrounds, cards |
| `--border` | `#252220` | `#d8d1c4` | Hairline borders, dividers |
| `--border-strong` | `#3a342d` | `#c4b9a6` | Button and input borders |
| `--text` | `#e6e1d6` | `#1c1a17` | Primary text |
| `--muted` | `#948a7c` | `#6b6152` | Secondary text, labels (≥ 4.5:1, WCAG AA) |
| `--faint` | `#6a6358` | `#9a8f80` | Decorative only; too low‑contrast for text |
| `--accent` | `#c08030` | `#8a5712` | Amber highlight, links, active state (light value darkened for AA) |
| `--accent-dim` | `#6a4818` | `#c89050` | Borders and hovers only; not for text |

The status service adds state colors (`--up`, `--degraded`, `--down`) for its badges.

### Layout, motion, accessibility

- **Canvas:** `font-size: 14px; line-height: 1.75`, content `max-width: 680–760px`, centered, `padding: 48px 32px 72px` (mobile `28px 18px 52px`). **Mobile‑first**: the Samsung S26 Ultra is the primary device.
- **Theme before first paint:** a synchronous `/theme.js` in `<head>` reads the `lf_theme` cookie, then `localStorage`, then `prefers-color-scheme`. Mark every `<script>` `data-cfasync="false"` so Cloudflare Rocket Loader doesn't defer it.
- **Grain overlay:** a fixed, pointer‑events‑none SVG `feTurbulence` layer at `opacity: 0.28`.
- **Entrance animation:** `rise` — `opacity: 0; translateY(18px)` → settled — at `0.9s cubic-bezier(0.16,1,0.3,1)`, staggered.
- **Accessibility baseline** on every site:
  - `:focus-visible` outline in `--accent`;
  - `prefers-reduced-motion` disables animations;
  - tap targets ≥ 24 px;
  - `aria-pressed` on the PT/EN buttons and an `aria-label` on ◐;
  - an `aria-live` region for "copiado!"-style feedback;
  - a skip link.

  Checked with axe‑core (no serious/critical violations) in both themes.

### Shared components

## Shared conventions

- **No build step, no framework, no bundler.** Hand‑written HTML/CSS/JS served statically (Pages) or from a single Worker file.
- **Deploy by pushing** to `main`.
- **Bilingual:** PT‑BR primary, EN secondary, toggled client‑side; the choice is shared across subdomains through the `lf_lang` cookie.
- **Dark/light theme** shared through the `lf_theme` cookie, restored before paint.
- **CSP without `'unsafe-inline'` scripts.** Put JavaScript in files (`script-src 'self'`) and wire events with `addEventListener` — never `onclick=`. Sites that must keep a script inline (the dash app) pin it by `sha256` hash and have CI fail when the hash drifts.
- **Self‑hosted fonts**, `font-src 'self'`.
- **Cloudflare `_redirects`** for short links: `/<slug>  <dest>  302` (301 only for links marked permanent).
- **Don't edit generated files by hand.** Every file dash writes starts with a `generated by dash.lucafchala.com (genX)` marker. Change them through dash:
  - `_redirects`, `404.*`
  - `url`'s `index.html` / `url.js` / `data.json`
  - paste shells, `pastes.json`, paste `sitemap.xml`

## Technical decisions

- **Why no framework / build step?** The content is small and changes rarely. Plain files mean zero toolchain rot, instant deploys and pages that still open years from now; some copy‑pasted CSS between repos is the accepted cost.
- **Why every site in its own repo and subdomain?** Independent blast radius and deploys, and each project can use the platform that fits it.
- **Why GitHub as the database for dash?** The data already has to live in git to deploy. The dash commits to git through a small server‑side proxy (so the token never reaches the browser), and Cloudflare turns those commits into deploys.
- **Why external scripts instead of CSP hashes?** Hashes have to be regenerated on every edit. Cloudflare's Rocket Loader also rewrites inline handlers at the edge, which changes their hashes; the 404 needed six hashes plus `'unsafe-hashes'` just to run. A script served from `'self'` needs none of that.
- **Why 302 for short links?** They are meant to be retargeted (event galleries moved from Drive to `fotos`), and browsers never re‑check a cached 301.
- **Why Cloudflare?** Free static hosting plus Workers, KV, D1 and Pages Functions under one account, automatic HTTPS, and a global edge.
