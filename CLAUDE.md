# Codebase Overview

Personal website for Luca F. Chala. Static site, no build step, deployed automatically via Cloudflare Pages on every push to `main`.

## Structure

```
index.html          # Main landing page (hero, 01 Fotografia, 02 Rádio, 03 Contato, 04 Ecossistema, 05 Verificação)
404.html            # Custom 404 page (generated by dash — don't hand-edit)
transferring.html   # Migration notice (for pages moving off omg.lol)
_redirects          # Cloudflare Pages redirect rules (301s) (generated by dash — don't hand-edit)
_headers            # Cloudflare Pages response headers (CSP, HSTS, Link, cache)
robots.txt          # Crawl rules + AI Content-Signal preferences + sitemap ref
sitemap.xml         # Canonical URLs for this deployment
llms.txt            # Plain-text summary for LLMs/agents
manifest.json       # PWA manifest (icons, shortcuts)
fonts/              # Self-hosted woff2 (Cormorant Garamond normal+italic, JetBrains Mono) — latin subset, variable weight, OFL
favicon.svg, icon.svg, icon-*.png, apple-touch-icon.png, og.png, og.svg
status/
  index.html        # Redirect to status.lucafchala.com (the real dashboard)
```

## Key facts

- **No framework, no build tool** — pure HTML, CSS, vanilla JS. Just edit and push.
- **Bilingual** — Portuguese (BR) and English, switched client-side. Strings live in the `i18n` object in `index.html`; elements carry `data-i18n="key"` (innerHTML) or `data-i18n-aria="key"` (aria-label). The PT text in the markup is the no-JS fallback, so keep both in sync. First visit picks the language from `navigator.language`; the choice is saved in `localStorage.lang`.
- **Dark/light theme** — follows `prefers-color-scheme` until the visitor toggles it; the choice is saved in `localStorage.theme` and applied by the tiny head script before first paint.
- **Command palette** — `/` or ⌘K/Ctrl+K opens a `<dialog>` built automatically from every link inside `main section[id]` and the footer, plus a few actions. New links show up in it for free. `T` toggles theme, `L` toggles language.
- **Content that goes stale** — the "Galerias recentes" list (hand-picked from fotos.lucafchala.com), the camera kit summary (from paste.lucafchala.com/camera-gear) and the radio station details (from radio.lucafchala.com/pu2xik) are static snapshots. Update them when those change. fotos/status don't send CORS headers, so the homepage can't fetch them live.
- **`_redirects`** — Cloudflare Pages syntax (`/path  https://dest  301`). Covers social links, event galleries, video downloads, and tools. Generated by dash.
- **`status/index.html`** — a script-free redirect (meta refresh) to `https://status.lucafchala.com`, the canonical dashboard, which runs server-side functional checks of every service.
- **Easter eggs** (keep them working): hold the first `.callsign` → radio sweep; five quick taps on `.name` → Morse "CQ DE PU2XIK"; styled console signature.

## Content-Security-Policy

`_headers` pins every executable inline `<script>` (the head theme script and the
main app script in `index.html`, plus the two scripts in the dash-generated
`404.html`) with `sha256-` hashes instead of `'unsafe-inline'`. The 404's two
inline `onclick=` handlers are allowed via `'unsafe-hashes'` + their hashes —
both as written and in the form Rocket Loader rewrites them to at the edge
(`if (!window.__cfRLUnblockHandlers) return false; …`).
The JSON-LD block is not executed and needs no hash.
**If you edit any inline script, regenerate the hashes** or the page's JS will
be blocked — CI (`checks.yml` → "CSP hashes cover every inline script") fails
when they drift. This rewrites the `script-src` directive in place:

```bash
python3 - <<'PY'
import re, hashlib, base64
h = lambda x: "'sha256-" + base64.b64encode(hashlib.sha256(x.encode()).digest()).decode() + "'"
scripts, handlers = [], []
for f in ('index.html', '404.html'):
    html = open(f, encoding='utf-8').read()
    for m in re.finditer(r'<script\b([^>]*)>(.*?)</script>', html, re.DOTALL):
        if 'src=' in m.group(1) or 'ld+json' in m.group(1) or not m.group(2).strip(): continue
        scripts.append(h(m.group(2)))
    for v in re.findall(r'\son[a-z]+="([^"]*)"', html):
        # Rocket Loader rewrites each handler at the edge; allow both forms.
        handlers += [h(v), h('if (!window.__cfRLUnblockHandlers) return false; ' + v)]
src = "script-src 'self' " + ' '.join(scripts) + (" 'unsafe-hashes' " + ' '.join(handlers) if handlers else '') + " https://static.cloudflareinsights.com"
hd = open('_headers', encoding='utf-8').read()
open('_headers', 'w', encoding='utf-8').write(re.sub(r"script-src [^;]*", src, hd, count=1))
PY
```

Inline event handlers (`onclick=`…) are intentionally avoided in `index.html`
for the same reason — wire events with `addEventListener` in the main script.

### Cloudflare zone rewrites (production only)

The zone has **Rocket Loader** and **Cloudflare Fonts** enabled, which rewrite
the served HTML (not the repo):

- Rocket Loader would defer inline scripts (theme flash). Every inline script in
  `index.html` carries `data-cfasync="false"` to opt out — keep it on new ones.
- Cloudflare Fonts replaces Google Fonts `<link>`s with `@font-face` rules served
  from `/cf-fonts/` (same origin). That's why `font-src` includes `'self'`
  — before, every font on the live site was CSP-blocked. The homepage now
  self-hosts its fonts from `/fonts/` and doesn't touch Google at all.
- Cloudflare Web Analytics injects `static.cloudflareinsights.com/beacon.min.js`
  and posts to `cloudflareinsights.com` — both are allowed in the CSP.

## Deployment

Push to `main` → Cloudflare Pages deploys automatically. No build command. CI (`.github/workflows/checks.yml`) validates JSON, internal links and CSP hashes; `smoke-test.yml` hits key routes after each deploy.
