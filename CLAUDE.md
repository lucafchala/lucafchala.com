# Codebase Overview

Personal website for Luca F. Chala and hub of the `*.lucafchala.com` ecosystem. Static site, no build step, deployed automatically by Cloudflare Pages on every push to `main`. The ecosystem map, design system and shared conventions are in `README.md`; read it before changing anything visual.

## Structure

```
index.html          # Landing page markup (hero, 01 Fotografia, 02 Rádio, 03 Contato, 04 Ecossistema, 05 Verificação)
style.css           # All homepage styles
app.js              # All homepage behaviour (i18n, palette, clock, copy, easter eggs, WebMCP)
theme.js            # Sync <head> script: applies the theme before first paint
404.html, 404.js    # Shared 404 — GENERATED by dash (gen404Html / gen404Js), don't hand-edit
_redirects          # PURL rules — GENERATED by dash (genRedirectsFile), don't hand-edit
_headers            # Response headers (CSP, HSTS, COOP/CORP, Link, cache)
transferring.html   # Migration notice (pages moved off omg.lol)
status/index.html   # Meta-refresh to status.lucafchala.com
robots.txt, sitemap.xml, llms.txt, manifest.json, .well-known/
fonts/              # Self-hosted woff2 (Cormorant Garamond normal+italic, JetBrains Mono) — latin, variable, OFL
favicon.svg, icon.svg, icon-*.png, apple-touch-icon.png, og.png, og.svg
todo.md             # Open follow-ups (also tracked as GitHub issues)
```

## Key facts

- **No framework, no build tool.** Pure HTML, CSS, vanilla JS. Edit and push.
- **HTML / CSS / JS are separate files.** Keep them that way: markup in `index.html`, styles in `style.css`, behaviour in `app.js`. The JSON‑LD block in `<head>` is the only inline `<script>`; it's data and never executes.
- **Bilingual.** Strings live in the `i18n` object in `app.js`. Elements carry `data-i18n="key"` (innerHTML) or `data-i18n-aria="key"` (aria-label). The PT text in the markup is the no‑JS fallback, so keep both in sync.
- **Theme and language are shared across subdomains.** Choices are stored in the `lf_theme` / `lf_lang` cookies on `.lucafchala.com` (see `store` in `app.js` and `theme.js`), with `localStorage` as a fallback. Every sibling site reads the same cookies. Without a saved choice, the theme follows `prefers-color-scheme` and the language follows `navigator.language`.
- **Command palette:** `/` or ⌘K/Ctrl+K opens a `<dialog>` built automatically from every link inside `main section[id]` and the footer. New links show up in it for free. `T` toggles theme, `L` toggles language.
- **Live status dots** (04 Ecossistema, `loadLive`/`renderLive` in `app.js`):
  - read `status.lucafchala.com/api/resumo` (~1 KB, CORS `*`, reads the D1 snapshot only) and draw only when `retratoCompartilhado` is true;
  - `/api/painel` has no CORS and is ~90 KB — reading it is what kept the dots from ever showing (status#52);
  - never switch them to `/api/status`, which sweeps every subdomain per request;
  - matching is by the card link's hostname.
- **"Galerias recentes"** (01 Fotografia, `loadGalleries` in `app.js`) updates itself:
  - after `load` it reads `fotos.lucafchala.com/api/recentes` (CORS `*`, 5 min cache): up to 5 public galleries in the fotos gallery's order (pinned first), without hidden/private/family ones;
  - the response shape (`{galerias:[{slug, titulo, data, url, destaque, emBreve}]}`) is a contract with fotos (`handleRecentes`); change both together;
  - links are built from the validated slug, never from the response's `url`; titles stay PT in EN mode;
  - the list in `index.html` is only the no‑JS/offline fallback, replaced when the API returns at least one valid item. Refresh it now and then, but nothing breaks if it lags.
- **Content that goes stale:** the camera kit summary (from paste.lucafchala.com/camera-gear) and the radio details (from radio.lucafchala.com/pu2xik) are static snapshots. Update them when those change.
- **Generated files:** `_redirects`, `404.html`, `404.js` come from dash and start with a "generated by dash.lucafchala.com" marker. Change them in the dash (`/home/.../dash.lucafchala.com/index.html`, functions `genRedirectsFile`, `gen404Html`, `gen404Js`). The next PURL save there overwrites hand edits.
- **Short links are 302 by default** (301 only when marked permanent in dash). Cloudflare applies `_redirects` before static files, so a slug named like a file here would shadow it; dash has a reserved list.
- **Easter eggs** (keep them working): hold the first `.callsign` → radio sweep; five quick taps on `.name` → Morse "CQ DE PU2XIK"; styled console signature.
- **Footer credit:** "HTML, CSS e JS puros · feito com ajuda do Claude". Don't claim the site is hand‑made.

## Content-Security-Policy

`_headers` sets `script-src 'self' https://static.cloudflareinsights.com`, with no hashes and no `'unsafe-inline'`:

- **Never add an inline `<script>` or an `on*=` attribute.** Put code in `app.js` (or a new file) and use `addEventListener`.
- CI (`checks.yml` → "CSP hashes cover every inline script") fails if any executable inline script or handler appears in any `.html` file, since none is allowed.
- `style-src` allows `'unsafe-inline'` (a few style attributes remain in the markup); `font-src 'self'`.

### Cloudflare zone rewrites (production only)

State as of 2026-09-25 (lucafchala.com#18). The zone rewrites the served HTML, not the repo:

- **Rocket Loader: off.** Every `<script>` still carries `data-cfasync="false"` so a future re-enable leaves it alone. Keep it on new ones.
- **Cloudflare Fonts: off.** We self‑host anyway.
- **Email Obfuscation: on** (owner's decision). It rewrites addresses in the HTML to `__cf_email__` and injects `/cdn-cgi/…/email-decode.min.js` (same‑origin, so `'self'` covers it). Pages that render addresses from JS/JSON (paste) show them normally.
- **Web Analytics: manual snippet on the homepage only.** Automatic injection is off on every hostname. `index.html` loads `static.cloudflareinsights.com/beacon.min.js` with `data-cf-beacon='{"token": "…"}'` (the token is public; it's the site token from Cloudflare → Web Analytics → lucafchala.com → Manage site). It's allowed in `script-src` and `connect-src` here only. The snippet counts EU visitors too; the old automatic mode excluded them. CI fails while the token is the `__CF_BEACON_TOKEN__` placeholder.
- **JavaScript Detections: on, and can't be turned off from the Free dashboard.** It injects an inline `window.__CF$cv$params=…` script on every page; the CSP blocks it (a console error, nothing breaks). The API route to try is in #18.

## Local preview

`python3 -m http.server` works, but doesn't apply `_headers` or `_redirects`. To test the CSP, serve with something that honours `_headers`, or check the page in production after deploy (`smoke-test.yml` does basic checks).

## Deployment

Push to `main` → Cloudflare Pages deploys automatically. No build command. CI:
- `.github/workflows/checks.yml` validates JSON, internal links and the no‑inline‑script rule.
- `smoke-test.yml` runs on push to `main`, daily, and on demand:
  - it waits for the deploy by hashing a changed static file (HTML can't be compared: the zone rewrites it);
  - then it checks the key routes, the CSP header, `/instagram` and `/pgp`, the 404, and `security.txt` expiry.
- `checks.yml` runs monthly too, so an expiring `security.txt` turns CI red. Renew it here and in proof together.
